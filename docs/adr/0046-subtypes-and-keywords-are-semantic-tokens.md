# 46. Subtypes and keywords are semantic tokens

Date: 2026-09-02

## Status

Accepted. Extended by [ADR-0048](0048-membership-is-a-third-direction.md), which
adds the `has` direction these families mostly live in.

> **Number 0046 is taken by this ADR.** 0045 and 0047 were claimed by concurrent
> agents. The next agent should take 0049.

## Context

The user asked for something short and very large:

> "I would also make each keyword a semantic token. also, each type and subtype
> should be a semantic token, and have their relevant relationships. that also
> means if a card references a type like 'Untap all Forests' we should tag it
> with both untap and Forest"

Measured before writing anything, over the **31,782 commander-legal cards** in
the corpus:

| | |
| --- | --- |
| distinct keywords | 880 (813 on commander-legal cards) |
| distinct subtype words | 546 (431 on commander-legal cards) |
| synergy tags today | 21 |
| synergy tags per card today | 1.82 |

So the ask is roughly a **sixty-eightfold expansion of the vocabulary**, against
a model whose every part assumes the vocabulary is small and hand-curated:
`INTERACTION_PAIRS` is hand-written pairs, `apps/web/src/tags.ts` is one
hand-written phrase per tag with a test asserting none is missing, and the
filter's error message prints the whole vocabulary on a typo.

## Decision

Two new tag families, namespaced and generated from the corpus:

- `subtype:elf`, `subtype:forest`, `subtype:equipment`, `subtype:saga`
- `ability:flying`, `ability:first-strike`

**586 tags: 269 subtypes and 317 keywords.** The vocabulary is a generated,
committed data file — `packages/domain/src/semantic-vocabulary.data.json`,
following `brackets/rules.data.json` — regenerated by
`apps/ingest/src/semantic-vocabulary.ts`, because `packages/domain` is pure (R1)
and cannot read a table.

### The base relation does all the work. No new pairs.

This was the load-bearing thing to verify rather than assume, and it holds:

| card | direction |
| --- | --- |
| Elvish Archdruid — "Other Elf creatures you control get +1/+1" | **wants** `subtype:elf` |
| every Elf, by its type line | **has** `subtype:elf` |
| Favorable Winds — "Creatures you control with flying get +1/+1" | **wants** `ability:flying` |
| Llanowar Druid — "{T}, Sacrifice this creature: Untap all Forests" | `untap` + **wants** `subtype:forest` |

Tribal synergy falls out of same-tag-opposite-direction, which the model already
had. **`INTERACTION_PAIRS` gains nothing**, and the obvious candidates were
checked rather than waved off: an Equipment's type line already produces
`artifact-etb` and an Aura's already produces `enchantment-etb`, so a pair would
be a second name for a claim the file already makes.

The user's worked example is a test:
`{T}, Sacrifice this creature: Untap all Forests` derives `creature-death`,
`untap`, `has: subtype:elf, subtype:druid` and `wants: subtype:forest`.

### The refusals, each with its measurement

**1. Card types and supertypes — all 14.** `Creature` alone is 17,751 cards,
**55.9% of the corpus**. A tag that broad pairs with everything and distinguishes
nothing, which is the ground ADR-0029 §6 refused a mill tag on. `t:` already
filters types, composition already counts them, and where a type names an event
the curated table already owns it — `artifact-etb`, `enchantment-etb` and
`spell-cast` are literally "this card IS an artifact / an enchantment / an
instant or sorcery".

**2. One-offs, in both families.** A token printed on a single card groups
nothing with anything. **489 of 813 keywords** go this way, because Scryfall
files bespoke ability words under `keywords` — "Allons-y!", "Bad Wolf", "Sense
the Good", "I. AM. TALKING!". Three subtypes go with them.

**3. Subtypes nothing in the corpus NAMES.** 113 of the survivors. Provable
inertness rather than a threshold: a tag with no wanter can appear in none of the
directions `synergyMatches` scores, and `t:` answers "is this an Elf" better than
a tag would anyway.

The two subtype rules are not the same rule and both fire: of 161 refused
subtypes, **3 fall to the one-off floor alone, 113 to inertness alone, and 45 to
both**.

**4. Four type-line parse artefacts, by name.** `of` (Miss Demeanor, "Lady OF
Proper Etiquette"), `You`, `The` (B.F.M.) and `and/or` (Shellephant). Naming them
matters because the inertness rule cannot catch two of them: `You` and `The`
appear in thousands of cards' rules text, so each would have sailed through on
one producer and four thousand wanters and become the broadest tags in the
vocabulary.

**5. `subtype:treasure`**, a second name for the existing `treasure` event tag.
Food, Clue and Blood are not duplicates and stay.

### Keywords are vocabulary, not scoring, and the ADR says so

Written out as honest payoff templates — "creatures with X get", "whenever … with
X", "for each … with X", "as long as … with X" — **only 25 of 813 keywords have
any payoff card in the corpus at all**, 137 payoff cards in total. Everything
that *looks* like a keyword payoff is one of three things that is not one:
reminder text (Reach prints "(This creature can block creatures with flying.)",
which made all 417 Spiders look like flying payoffs), a grant, or a token.
A naive word match gave `flying` 695 wanters; the honest count is 73.

The owner's ruling was to keep all keywords except the one-offs, and the reason
is that a keyword is worth **filtering on** whether or not anything pays it off.
That is accepted here and stated plainly rather than implied: **of the 317
keywords kept, 19 have a payoff card and can score. The other 298 can appear in
no match direction.** The generator prints that split on every run so it cannot
quietly rot.

### Planeswalker subtypes: membership by the same rule, rendering by another

An earlier draft refused all 80 planeswalker subtypes as a class, on the grounds
that they are proper names. That was a **rendering** concern wearing a
**membership** rule's clothes, and mixing the two is how they drift apart. The
one-off floor decides membership like everything else; **33 survive**, every one
printed on two or more cards (Chandra 21, Ajani 15, Jace 15, down to Basri and
Tyvar at 2), and they are real — "As long as you control a Rowan planeswalker",
"If you control a Bolas planeswalker".

The rendering concern is answered where it belongs: the vocabulary records
`properNouns`, and `displaySubtype` does not pluralise them. "Chandras" is not a
word.

### Spelling: namespaced, lowercase-kebab, and NOT `type:`/`kw:`

Bare names collide — `Treasure` is an artifact subtype and an existing tag;
`Landfall`, `Mill`, `Food` and `Flashback` are Scryfall keywords and existing
tags — and `normaliseTag` lowercases every value the search box takes, so case
cannot be the discriminator.

The prefix is `subtype:`/`ability:` and deliberately not `type:`/`kw:`, because
**those two are already query FIELD aliases**: `kw:flying` means "has the Flying
keyword" in the search box, and a tag value spelled the same way one colon over
would be two meanings for one string. The tokenizer takes the earliest operator,
so `produces:subtype:elf` splits at the first colon and the value keeps its own —
no quoting needed.

### Display phrases are derived, not written

`apps/web/src/tags.ts` holds one hand-written phrase per curated event and a test
asserting none is missing. That table cannot grow to 586 and does not have to: a
subtype's words are the subtype and a keyword's are the keyword. The test now
splits — hand-written words required for the 24 curated events, derived words
required for the 586 generated ones — and **neither half may fall through to the
hyphen-stripper**.

## Consequences

### The frequency worry was aimed at the wrong tags

Tags carried by more than 10% of the corpus, in order:

| tag | cards | share |
| --- | --- | --- |
| `spell-cast` | 7,908 | 24.9% |
| **`subtype:human`** | 4,579 | **14.4%** |
| `artifact-etb` | 4,369 | 13.7% |
| `creature-etb` | 4,072 | 12.8% |
| `card-draw` | 4,048 | 12.7% |
| `token` | 4,040 | 12.7% |
| `untap` | 3,784 | 11.9% |
| `enchantment-etb` | 3,683 | 11.6% |

Six of the eight are existing curated event tags, and `spell-cast` dwarfs
everything. `ability:flying` comes ninth at 10.0%. `subtype:human` is kept: it is
self-limiting because supply-side tags are not scored against each other, and it
has 165 real payoffs.

### Size

The vocabulary grows about twelvefold and the tag load per card less than
doubles, which is the gap that makes this affordable at all:

| | today | after |
| --- | --- | --- |
| tags per card | 1.82 | 3.77 |
| p50 / p90 / p99 / max | | 3 / 6 / 10 / 26 |

Storage: measured on `pg_column_size` over the eligible rows, the tag columns add
**1.247 MiB**. `findEligibleCards` was changed from `SELECT *` to a named column
list in the same pass — ADR-0017's argument, applied to the read
`corpus-cache.ts` flags as the untrimmed one — which gives back **0.396 MiB**,
for a net of **+0.851 MiB** on a 16.79 MiB row set. `oracle_text` cannot be
dropped: the `oracle:` predicate, `cardImpact` and `fixing` all run over the whole
eligible pool at request time. `default_printing` is the next 0.485 MiB and is
left, because taking it needs the read to return a type narrower than `Card`
rather than a `Card` with a hole in it — precisely the failure ADR-0017 warns
about.

### Emphasis needs a real cap now

`semantic-emphasis.ts` argued for no length cap because "deduplication already
bounds the value at `SYNERGY_TAGS.length` (19 today)". That bound is 608 now. The
cap is **12**, and it is enforced in two places with different behaviour on
purpose: the **API rejects** an oversized value with `maxItems` in the 400,
because a client told it saved fifteen when twelve were kept has a bug it cannot
see; the **domain truncates** on read, because a row written by an older build
must stay openable.

### The filter's error message

It used to join the whole vocabulary into one suggestion string, on the stated
ground that "the list is short and closed … showing all seventeen". At 608 tags
that is several kilobytes rendered under a search box. It is a near-miss list
now, ranked by shared leading characters so a transposition still finds its
target, capped at six — following what `is:` already did one branch up.

### Rejected: hand-writing any of it

Considered and refused for the obvious reason, but worth recording what would
have had to be hand-written: 586 display phrases, and a relationship table over a
vocabulary whose pair space is 10⁶. The measurement that made the decision easy
is that neither is needed — the phrases derive from the tag and the relationships
are the base relation.

### Found and not done

- **The eligible-card read still carries `default_printing`** (0.485 MiB) and
  still populates a `Map<OracleId, Card>` in `deck-context.ts` with 30k entries
  that are then either overwritten or never read. Both need the read to return a
  narrower type, which is a change to a hot path this ADR does not own.
- **The GIN indexes on `synergy_produces` and `synergy_wants` appear unused.**
  Both predicates are evaluated in the application, and `findEligibleCards`
  filters only on legality and colour identity. Migration 0003's stated reason
  for them — "an array-overlap query in both directions" — describes a query
  nothing makes.
